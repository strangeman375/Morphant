# Generated artifacts

Morphant emits only artifacts required by eligible destinations, mapping
pairs, and attributed mapper classes.

| Artifact kind | Stable owner | Purpose |
|---|---|---|
| `Construction` | Destination | Generated structured construction surface |
| `Member` | Destination | Generated member-plan surface |
| `MappingExtension` | Source/destination pair | `Construct` and `Convert` fluent extensions |
| `MemberExtension` | Source/destination pair | `Members` fluent extensions |
| `TypeMapper` | Concrete attributed mapper | Executable `ITypeMapper<,>` implementations |

Hint names use:

```text
Morphant.Generated.<ArtifactKind>.<StableIdentity>.g.cs
```

Identities are deterministic and readable. A stable hash suffix is added only
when two files of the same artifact kind have a real case-insensitive hint-name
collision after sanitization. Adding or removing an unrelated mapping does not
renumber neighboring files.

Destination-owned construction and member surfaces are deduplicated across
all mappings that use the same canonical destination. Pair extensions and
mapper implementations remain pair/mapper owned. Unsupported capabilities do
not produce placeholder compatibility files.

Generated files use deterministic CRLF line endings, start with
`// <auto-generated />`, and enable nullable annotations. A destination in the
global namespace uses `Morphant.Generated`; Morphant does not synthesize a
fake `Global` namespace segment.

The generated construction/member records are compile-time DSL surfaces.
Their runtime bodies intentionally throw if invoked as ordinary application
code. The executable behavior lives in the generated partial mapper.
