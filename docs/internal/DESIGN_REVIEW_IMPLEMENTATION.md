# Реализация решений ревью дизайна

Составлено 2026-11-19 по итогам [ревью дизайна](DESIGN_REVIEW.md). Номера в
скобках — пункты ревью; обоснования и точные формулировки решений — там.

## Как отмечать

- Пункт отмечается `[x]` с коротким хешем завершающего коммита, когда
  выполнены общие критерии готовности. Пункт может занимать несколько коммитов.
- Если пункт с условием не выполняется (например, 10.2 или 13.2), он
  отмечается `[-]` с причиной в одну строку.

Общие критерии готовности пункта:

- код и тесты по [правилам тестирования](TESTING_GUIDELINES.md), для изменений
  генерации — просмотренные снимки полного сгенерированного кода;
- обновлены затронутые руководства, API, настройки, справка диагностик и
  ограничения; изменённый контракт генератора записан в
  [GENERATOR_CONTRACTS.md](GENERATOR_CONTRACTS.md);
- запись в разделе `[Unreleased]` changelog для наблюдаемого изменения.

## Выпуск 0.6.0: ломающие изменения и диагностики

Этапы 0–6 выходят одной версией 0.6.0 с инструкцией миграции, а не по
отдельности. Порядок задан зависимостями: каждый следующий этап опирается на
поверхности и семантику предыдущего.

### Этап 0. Двоичная совместимость

Первый выпуск с ломающими изменениями runtime уже должен содержать проверку.

- [x] До 1.0 библиотеки и приложение используют одну minor-линию Morphant.
  Начиная с 1.0 runtime совместим с библиотеками, собранными предыдущими
  версиями той же major-линии (17.2, [политика версий](../compatibility.md)). `b11f0163`
- [x] `MORPH0063` проверяет версию runtime в метаданных DLL, переданной
  компилятору, включая библиотеки, собранные с Morphant 0.5.
  `AssemblyVersion` выводится из `Version`. Границы проверки для ссылок на
  исходный проект и reference assembly описаны и покрыты тестами (17.2). `cb36ea2c`

### Этап 1. Объявление маппера без CRTP

Самое большое изменение API; от новых поверхностей зависят все следующие
этапы.

- [x] Необобщённый `TypeMapper` и общие для сборки поверхности на CLR-пару;
  удалить `MORPH0058`, `MORPH0059` и `MORPH0060`, оставив их страницы с
  пометкой об удалении; поднять ревизию `Morphant.GeneratorContractVersion` до 3 (1.8, 17.2). `6f9737df`
- [x] Одно представление CLR-пары на сборку с `MORPH0056`. Для открытых пар
  генерируются обобщённые расширения. `MORPH0064` указывает на неоднозначное
  пересечение, а [`MORPH0065`](../diagnostics/MORPH0065.md) — на конфликт
  с расширением, видимым через `InternalsVisibleTo` (1.8). `9967d4ee`
- [x] `Convert`, `ConstructUsing` и `ResolveUsing` возвращают `Destination?`.
  Маппер реализует `ITypeMapper<Source, Destination>`. `IncludeMembers`
  генерируется для подходящих пар с источником как у `Members` (1.8). `777b0d88`
- [x] Примеры документации без self-типа; инструкция миграции на
  необобщённый `TypeMapper` (1.8). `5846f51a`

### Этап 2. Модель вложенных вызовов и сгенерированный код

Прямые вызовы, контекст, встроенный код и имена методов меняют один и тот же
сгенерированный код. Первым идёт контекст: на нём строятся прямые вызовы.

- [ ] Производный контекст: скрытый API, тот же `MappingScope`, операция
  вложенного вызова, текущий маппер, без аллокаций на вызов (17.3).
- [ ] Прямые вызовы пар, реализованных маппером (1.1); `context.Mapper`
  выполняет пары текущего маппера напрямую, остальные — через тот же scope
  (2.2).
- [ ] Генерируемый маппер может наследоваться от генерируемого;
  унаследованные реализованные пары считаются его парами для прямых вызовов
  (9.1).
- [ ] Встроить `UpdateInPlace` и `UpdateDerived`, удалить `MappingHelpers`,
  записать правило о runtime-хелперах в контракт генератора (13.1).
- [ ] Стабильные имена сгенерированных методов, не зависящие от порядка, если
  уникальность достижима без перегруженных имён; иначе оставить нумерацию
  (13.2).

### Этап 3. Семантика и значения по умолчанию

Изменения поведения, на которые опираются диагностики этапа 4: тексты и
условия предупреждений зависят от новой семантики.

- [ ] Модель значений `Members`: `Ignore()` действует на связанный
  автоматический параметр конструктора; взаимодействие с
  `ConstructorSelection`; связь видна в IntelliSense и руководстве `Members`
  (5.1).
- [ ] Read-only член: setter на поверхности `Members`, `Map()` обновляет
  значение на месте, значение и `Create(...)` — ошибка; удалить
  форму-инструкцию с именем сгенерированного типа (7.3).
- [ ] `NullSourceHandling.ReturnDestination` по умолчанию (8.1).
- [ ] `UnmappedMemberValidation.Destination` по умолчанию; взаимодействие с
  `MemberSelection.Explicit` в документации настройки (6.2, 17.5).

### Этап 4. Диагностики генератора

- [ ] Warning: совпавший по имени член, который конвенция не может
  использовать; только там, где конвенция применяется (6.1, 17.5).
- [ ] Ошибка: вложенный вызов пары текущего маппера требует операции,
  выключенной её `MappingMode`; warning: адаптивный `Map()` при внешнем Create
  передаёт подготовленное значение во вложенный Update, а правила пары задают
  creation-only члены (7.2).
- [ ] Warning nullability: вложенный source может быть `null`, а член
  non-nullable (8.2).
- [ ] Warning: вложенный вызов пары, объявленной в абстрактной базе только как
  шаблон (9.1); warning: пара наследника скрывает ту же пару базы (9.2).
- [ ] Полиморфная причина и исправление в `MORPH0035` (10.1); warning о
  производных типах без ссылки `ForDerived` — при приемлемой стоимости для
  инкрементальности (10.2).
- [ ] `MORPH0023` для любой явной настройки без эффекта (11.1); ошибка для
  повторной настройки на одном уровне (11.2).

### Этап 5. Анализатор

Отдельная сборка анализатора в пакете с общей инфраструктурой; каждое правило
реализуется при условии надёжности и низкой стоимости.

- [ ] Сборка анализатора и инфраструктура: символы DSL, operation actions,
  конкурентное выполнение (1.7).
- [ ] Ошибка: неабстрактный наследник `TypeMapper` без `[MorphantMapper]` у
  себя и баз (1.4).
- [ ] Ошибка: DSL-метод вызван вне `Configure`, отдельный ID (1.7).
- [ ] Warning: отброшенный результат Update для destination значимого типа и
  константы `null`/`default` (2.3).
- [ ] Warning: имена элементов кортежа на месте вызова отличаются от
  объявленного представления пары (12.1).

### Этап 6. Документация и выпуск

- [ ] Quick start: `Configure` читается генератором и не выполняется (3.3).
- [ ] Create и Update: для immutable-типа Update возвращает объект без
  изменений, замену выбирает `Resolve` (7.1).
- [ ] Провести [сквозную проверку документации](DOCUMENTATION_GUIDELINES.md#updating-and-publishing).
- [ ] Changelog и инструкция миграции для всех ломающих изменений, включая
  смену значений по умолчанию (6.2, 8.1) с настройками прежнего поведения;
  версия 0.6.0 в метаданных пакета; правило выпуска: с первого patch после
  0.6.0 `PackageValidationBaselineVersion` — предыдущий выпуск той же линии
  (17.2).
