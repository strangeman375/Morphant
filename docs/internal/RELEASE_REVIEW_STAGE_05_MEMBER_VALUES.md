# Единое значение параметра конструктора и члена

Пользователь пересмотрел S05-01 после проверки реализации `ba151fb`:
сохранение отдельного member-присваивания передавало конструктору значение,
не соответствующее явному правилу. Этот вариант больше не является целевым
контрактом. Исправление S05-02 сохраняется. Этап 6 не начинается.

## Согласованное правило

- Параметр конструктора и соответствующий destination-член используют одно
  правило значения. Сопоставление сохраняет текущую конвенцию: точное имя,
  затем единственное совпадение без учёта регистра.
- Явное `Members` задаёт итоговое значение связанного параметра, в том числе
  поверх `Construct` / construction-ветви `Resolve`, как для кортежей.
  Переопределённое выражение параметра не вычисляется.
- При создании вычислить значение один раз в читаемую локальную переменную
  и передать её конструктору. Повторное member-присваивание не генерировать.
- Исключение: `required` без `[SetsRequiredMembers]` требует initializer по
  правилам C#. В нём используется та же переменная, без повторного вычисления.
  С атрибутом или без `required` лишнее назначение не требуется.
- При обновлении существующего объекта значение применяется через доступный
  setter/поле; creation-only члены и неактивные выражения не вычисляются.
- Правила фабрик и преобразования готовых объектов сохраняют свой lifecycle.
  Типы, nullable-атрибуты и допустимость выбранного конструктора проверяются
  по существующим требованиям к C#-вызову.

```csharp
var value = source.Value + 100;
var result = new Destination(value);
```

Новые спорные сочетания, требующие изменения публичного поведения,
обсуждаются до их реализации; особенно важны зависимости от уже созданного
`result` и неоднозначное соответствие параметров и членов.

## Работа и проверка

1. Обновить автоматическое конструирование, `ByConvention`, явные
   `Construct` / `Resolve` и сохранение вычислений между ними и `Members`.
2. Заменить старые ожидания S05-01. Проверить реальное значение аргумента,
   число вычислений, вызовы setter и валидацию конструктора; set/init/required
   с атрибутом и без него, разные маршруты Create/Update, ветви и Ignore.
3. Проверить отсутствующий исходный одноимённый член, optional-параметры,
   nullable и преобразования, приоритет явных правил и неактивные выражения,
   читаемость/уникальность локальных имён и актуализацию на сохранённом driver.
4. Выполнить полные Release/unit/integration, затронутые категории Roslyn
   4.4.0/4.9.2 и повтор MSBuild-воспроизведений с новым контрактом.
5. Обновить публичные документы, план и итоговые результаты. Каждую
   содержательную контрольную точку публиковать в `main`.
