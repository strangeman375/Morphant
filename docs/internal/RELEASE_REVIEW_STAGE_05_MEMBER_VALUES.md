# Единое значение параметра конструктора и члена

Пользователь пересмотрел S05-01 после проверки реализации `ba151fb`:
сохранение отдельного member-присваивания передавало конструктору значение,
не соответствующее явному правилу. Этот вариант больше не является целевым
контрактом. Исправление S05-02 сохраняется. Этап 6 не начинается.

## Согласованное правило

- Параметр конструктора и соответствующий destination-член используют одно
  правило значения. Сопоставление сохраняет текущую конвенцию: точное имя,
  затем единственное совпадение без учёта регистра.
- Явное `Members` задаёт итоговое значение связанного параметра, в том числе
  поверх `Construct` / construction-ветви `Resolve`, как для кортежей.
  Переопределённое выражение параметра не вычисляется.
- При создании вычислить значение один раз в читаемую локальную переменную
  и передать её конструктору. Повторное member-присваивание не генерировать.
- Исключение: `required` без `[SetsRequiredMembers]` требует initializer по
  правилам C#. В нём используется та же переменная, без повторного вычисления.
  С атрибутом или без `required` лишнее назначение не требуется.
- При обновлении существующего объекта значение применяется через доступный
  setter/поле; creation-only члены и неактивные выражения не вычисляются.
- Правила фабрик и преобразования готовых объектов сохраняют свой lifecycle.
  Типы, nullable-атрибуты и допустимость выбранного конструктора проверяются
  по существующим требованиям к C#-вызову.

```csharp
var value = source.Value + 100;
var result = new Destination(value);
```

Новые спорные сочетания, требующие изменения публичного поведения,
обсуждаются до их реализации; особенно важны зависимости от уже созданного
`result` и неоднозначное соответствие параметров и членов.

## Контрольная точка: перенос значения

Автоматическое и явное конструирование передают member-выражение в аргумент
выбранного конструктора. Для `required` без атрибута initializer читает ту же
локальную переменную. Тип локальной переменной учитывает закрытие generic
маппер-семейства. Старые runtime-ожидания S05-01 заменены на новый контракт.

Направленный integration-прогон: 46 passed. Проверены четыре маршрута
конструирования, Create/Update(null)/Update(existing), set/init/required,
атрибут конструктора, число чтений и setter-вызовов, ветви и Ignore.

## Реализованное поведение

Основной перенос и выбор конструктора реализованы. `Members` учитывается до
поиска одноимённого source-члена, включая optional-параметры, `Auto()` и
аргументы `ByConvention`. Переопределённое выражение `Construct` не
вычисляется. Явно выбранная перегрузка конструктора сохраняется при
различающихся типах параметра и члена; допускается только совместимое значение.

Runtime-проверки используют конструктор, который отвергает неверный аргумент
и нормализует правильный. Это обнаруживает передачу прежнего значения и
повторный setter-вызов. Проверены исходник без одноимённого свойства,
бросающий исключение прежний аргумент, `Members.Auto()`, optional-параметры,
конструктор с перегрузками, set/init/required и shared dependencies.
Compiler-проверки покрывают nullable, AllowNull/DisallowNull, совместимость
типов и изменение доступности конструктора после удаления/возврата member-правила
на сохранённом driver. Полные снимки обычного и вложенного member-маппинга
обновлены под перенос значения в конструктор.

Контрольные точки: `29d5460` — основной перенос; `ee84ed8` — выбор конструктора;
`3e2823e` — дополнительные регрессии; `5cdfabc` — полные снимки;
`ae4cf11` — публичные документы.

## Согласованное дополнение: значение зависит от result

[Минимальное воспроизведение](release-review-stage-05/Cases/ResultDependency.cs)
фиксирует поведение до исправления зависимости от result:

```csharp
// Destination(int value) присваивает Value = value.
.Members((_, _, result) => new() { Value = result.Value + 10 });
```

При Source.Value = 7 конструктор получает 7, итоговое свойство равно 17,
счётчик назначений равен 2. Перенос этого выражения до конструктора невозможен:
для вычисления аргумента уже нужен создаваемый result.

2026-09-08 пользователь согласовал проверку достижимых веток и разрешил
реализацию. Любая достижимая ветка, обеспечивающая аргумент конструктора,
должна вычисляться без создаваемого `result`:

- Ограничение относится к фактическому созданию объекта, включая
  `Update(null)` и создание замены через `Resolve` в `Update(existing)`.
  Обновление с сохранением экземпляра не требует constructor-аргумента.
- Учитывать зависимость от `result` через local и условие выбора правила,
  а не только непосредственное чтение в выражении значения. Само наличие
  параметра `result` в callback не является причиной отказа.
- Условия `context.Operation` и наличия `previous` учитываются вместе с
  настройками и выбором destination. `Operation == Update` само по себе
  не доказывает наличие result; `previous` доступен до создания замены.
- Использовать существующий MORPH0042 о недоступном моменте применения
  member-правила: указать член, соответствующий параметр конструктора,
  зависимость и затронутые пути. При подавлении диагностики сохранить
  типизированный отказ затронутого пути и работоспособность остальных.
- Для фабрик и членов без соответствующего constructor-параметра действуют
  существующие ограничения set/init/required; общий запрет на `result` не нужен.

Статус: дополнение реализовано и проверено локально. Проверены прямое и
косвенное чтение, условные выражения и statements,
доступные и недоступные ветки операций, Create/Update(null)/reuse/replacement,
фабрики, несвязанные члены, точные диагностики, suppression и актуализация.
Этап 6 не начинается.

## Реализация дополнения о result

Окончательный код продукта: `58f4e67`; MSBuild-входы зафиксированы в
`d5b4f11`. Анализ разделяет Create, Update без previous и Update с previous.
Известные проверки операции/наличия previous исключают недостижимые ветки
до выбора constructor-значения. Учитываются `==`, `!=`, `is`, `is not`,
булевы комбинации, локальные зависимости и `switch`.

| Правило | Результат |
| --- | --- |
| `Value = result.Value + 10`, Value соответствует параметру конструктора | MORPH0042 для Create и Update(null); reuse работает |
| `Operation is Create ? 7 : result.Value + 10` | Create работает; при стандартных настройках MORPH0042 только для Update(null) |
| То же правило с NullDestinationHandling.Throw | Допустимо: null Update отклоняется настройкой |
| `previous.HasValue ? result.Value + 10 : 7` с сохранением previous | Обе ветки создания и reuse работают |
| То же правило в construction-ветви Resolve при наличии previous | MORPH0042 для замены: новый result ещё не создан |
| Чтение previous.Value вместо result в constructor-значении | Допустимо до создания замены |
| Runtime-фабрика или обычный член без соответствующего параметра | Сохраняется возможность читать готовый result в применимом member-правиле |

Кортежи сохраняют собственный контракт materialization/reconstruction,
описанный в [Tuple mapping](../tuple-mapping.md); их конструкция intrinsic
и не выбирается среди обычных destination-конструкторов. Полная проверка
кортежей остаётся этапу 7.

Добавлены 28 compiler-тестов и 15 runtime-тестов в MSBuild consumer.
Проверяются точный MORPH0042 без каскадных C#-предупреждений, ошибочная ветка

локальной переменной внутри вложенного делегата. Числовые локальные значения
не используются как известные факты об операции: C# promotions и равенство
